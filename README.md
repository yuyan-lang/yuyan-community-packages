# 豫言社区包仓库

这是豫言的社区包仓库：第三方包与豫言语言仓（[yuyan-lang/yuyan](https://github.com/yuyan-lang/yuyan)）的官方应用都以源码放在这里，经 CI 检查、构建后发布到 [yuyan-lang.org](https://yuyan-lang.org) 的包仓库。yuyan-lang.org 的包仓库只接受本仓库 CI 推送的程序。

## 目录

| 路径 | 内容 |
| --- | --- |
| `包/<所有者>/<包名>/` | 一个包一个目录：包描述 `<包名>。包。豫` 直接放在里面，连同源码、双语说明（`.汉语.md` 与 `.文言.md`）与许可证全文（`LICENSE`）。 |
| `包/豫言/` | 语言仓的官方应用，由语言仓 CI 每次推送后自动复制过来（许可 `AGPL-3.0-only`），请勿手改。 |
| `工具链钉。数据。豫` | 本仓库构建所用的语言仓原生工具链包（网址、沙256）与语言仓提交号，随语言仓的复制一起更新。 |
| `.github/` | CI 工作流。检查与构建程序是语言仓的[社区包工具](https://github.com/yuyan-lang/yuyan/tree/yybs/应用/开发工具/社区包工具)（`yy社区包工具`），它放在语言仓，拉取请求改不到它。 |

所有者名“社区”保留，不能用（包仓库的汇总软件目录用这个名字）。

## 一次性准备

1. 在 <https://yuyan-lang.org/个人> 注册豫言账户（暂时凭邀请码），验证邮箱，在豫言账户页 <https://yuyan-lang.org/cloud/账户/> 绑定所有者名称（例如 `张三`）。所有者名称绑定后不能改；你的包放在 `包/张三/` 下。
2. 关联 GitHub 账号：在账户页“GitHub 账号”一节填你的 GitHub 用户名，生成关联码（形如 `yygh_` 加 32 位十六进制，24 小时有效，只显示一次）。用这个 GitHub 账号在本仓库[开一个 issue](https://github.com/yuyan-lang/yuyan-community-packages/issues/new)，正文贴上关联码（标题随意）。机器人核对后回复并关闭 issue。关联码只能由你填写的那个 GitHub 账号使用。

## 提交一个包

1. Fork 本仓库，新建分支，把包放在 `包/<你的所有者名称>/<包名>/`。
2. 包描述 `<包名>。包。豫` 的写法见下例。依赖语言仓的库要写所有者“豫言”；「许可」必写，取下面白名单里的 SPDX 标识；不写「包含在」「包含包」。
3. 每个提交都带 DCO 签名：`git commit -s`（漏了就 `git rebase --signoff main` 补上）。
4. 向 `main` 开拉取请求。检查通过、你只改了自己名下的包，机器人就自动合入，无需人工审；第一次提交也一样。

```text
「名称」者『你好世界』也。

「所有者」者『张三』也。

「版本」者『0.1.0』也。

「类型」者「典」【「种类」者『可执行文件』也，「入口」者『入口』也，「文件名」者『yy你好世界』也】也。

「简介」者『打印“你好，世界”。』也。

「说明」者「典」【「汉语」者『说明.汉语.md』也，「文言」者『说明.文言.md』也】也。

「依赖」者「列」【「典」【「所有者」者『豫言』也，「包」者『标准库』也】】也。

「许可」者『MIT』也。
```

包的写法与工具见语言仓的[快速开始](https://github.com/yuyan-lang/yuyan/blob/yybs/应用/豫言编译器/文档/快速开始.汉语.md)与[包系统](https://github.com/yuyan-lang/yuyan/blob/yybs/应用/豫构/包系统.汉语.md)。本地检查与构建的做法见[贡献说明](CONTRIBUTING.md)。

## 检查与自动合入

- **拉取请求检查**（GitHub 托管运行机，不带机密）：
  - 元数据检查：改动的文件都在 `包/<所有者>/<包名>/` 里；不收符号链接、子模块与可能含凭据的文件；包布局、所有者、许可白名单与 DCO。
  - 构建与测试：在容器里（内存 12 GiB、不联网）把改动的包及依赖它们的包连同依赖闭包复制进独立构建树；库做类型检查，可执行包编成豫言系统 AMD64 豫行与 Linux x64 程序；运行包里的 `*。测试。豫`，每个至多十分钟。
- **合入机器人**（只看元数据，不检出也不运行拉取请求的代码）：拉取请求作者的 GitHub 账号在 yuyan-lang.org 关联的所有者，与改动的目录 `包/<所有者>/` 一致，改动全在其中，两项检查都通过，就自动合入。改了仓库本身文件（说明、工作流等）的拉取请求不自动合入，由维护者处理；工具链钉只有所有者“豫言”（语言仓 CI 的复制）可以随包一起改。

## 构建与发布

合入 `main` 后，CI 构建改动的包及依赖它们的包，推送到 yuyan-lang.org：

| 内容 | 地址 |
| --- | --- |
| 程序（五个目标：`豫言-兼容六十四`、`豫言-臂六十四`、`林纳克斯-兼容六十四`、`林纳克斯-臂六十四`、`苹果-臂六十四`） | `https://yuyan-lang.org/豫/<所有者>/包/<包名>/<版本>/程序/<目标>` |
| 每个所有者的软件目录 | `https://yuyan-lang.org/豫/<所有者>/软件/<目标>。数据。豫` |
| 全部社区程序的汇总目录（豫言系统的“安装软件”读它） | `https://yuyan-lang.org/豫/社区/软件/<目标>。数据。豫` |
| 源码与文档 | 包仓库里该包该版本的页面 |

软件目录是数据子语言（语言仓提案 00028）的记录列：顶层「软件们」，每个程序一个记录「软件」，字段为名称、版本、网址、沙二五六、字节数、简介、包名、所有者、提交。程序的版本是 `<包描述的版本>+<本仓库提交号前九位>`。豫言系统的目标在包根有「豫行入口」模块时用它作入口，苹果的目标在有「苹果入口」时用它，其余用包的默认入口。

## 许可

- 社区包只收这些许可（包描述「许可」字段写 SPDX 标识，可用 `AND`、`OR` 组合）：`Apache-2.0`、`MIT`、`BSD-2-Clause`、`BSD-3-Clause`、`ISC`、`Zlib`、`0BSD`、`AGPL-3.0-only`、`AGPL-3.0-or-later`。GPL 等其他传染性许可不收。包目录里请放许可证全文。
- 提交须带 DCO 签名（[Developer Certificate of Origin](https://developercertificate.org/)），表示你有权以所声明的许可提交这些代码。不要求签贡献者许可协议（CLA）。
- 从语言仓复制来的包一律是 `AGPL-3.0-only`（语言仓是 AGPL-3.0，并已有贡献协议）。
- 本仓库自己的脚本与 CI 配置用 Apache-2.0（见 [LICENSE](LICENSE)）；各包的许可以各自的「许可」字段与许可证文件为准。

## 发布条款要点

在 yuyan-lang.org 注册时，你同意发布条款：授权豫言项目托管你提交的包、编译它、为打包做必要的修改，并分发源码与编出的程序。
